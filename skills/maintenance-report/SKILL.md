# 检修建议报告写作规范

当用户拿到诊断结果(健康指数 HI、剩余寿命 RUL、缺陷判定、DGA 风险)后要求
"出一份检修建议 / 整理成报告 / 给运维方案"时,按下面的结构组织。

## 报告结构(五段式)

1. **设备概况**:设备 ID、变电站、诊断时间。
2. **健康评估结论**:HI(0-100)对应的等级 + RUL(年)。
   - HI ≥ 85:良好 | 70-85:注意 | 50-70:异常 | <50:严重
3. **主要风险**:三源融合判定的故障类型 + DGA 主要威胁 + 置信度。
4. **检修建议**(按紧迫度分级):
   - **立即**(HI<50 或检出电弧/高能放电):停电检查,必要时退运
   - **计划检修**(HI 50-70):纳入最近一次停电检修窗口
   - **加强监测**(HI 70-85):缩短带电检测/DGA 复测周期
   - **常规运维**(HI≥85):按标准周期
5. **依据**:引用相关标准条款(GB/T 7252、DL/T 722、Q/GDW 等)。

## 写作要点

- 数值**直接引用**诊断工具返回的 HI/RUL/风险评分,**不要自行估算或改动**。
- 若诊断结果里有 `forced_override`(严重缺陷强制覆盖 RUL/HI),必须在结论里
  显著说明覆盖原因,不能只报被覆盖后的数字。
- 建议要**可执行**:给出动作(停电/复测/红外/局放检测)+ 时间窗口,不要泛泛
  说"加强关注"。
- 语气专业、简洁,面向运维工程师。

## 输出格式

用 markdown,标题分节。结尾给一句话的总体处置意见(一行,便于工单系统摘取)。
