# HealthAgent 总览：变压器健康管控多智能体平台

> 一个面向电力变压器全寿命周期健康管控的多智能体系统:底层是**可复现、可审计的
> 确定性诊断内核**,外层是**LLM 驱动的自控对话编排**,用户用自然语言即可驱动诊断、
> 检索、历史分析与多设备并行处理。

---

## 一、它是什么

HealthAgent 把"变压器健康诊断"做成一个分层的智能体平台:

- **确定性诊断内核**:从时序数据取数 → BERT/CNN/YOLO 三源缺陷识别 → D-S 证据融合
  → 物理模型计算剩余寿命(RUL)→ 生成诊断报告。同样输入得到同样结果,可复现、可审计。
- **LLM 编排外壳**:一个自控的 Agent 循环,把上述内核包成可调用的能力,再加上知识、
  记忆、子智能体等,让用户用一句话("给 tr01 做体检")就能触发完整工作流。
- **多入口**:命令行 CLI、HTTP API、Web 前端(流式对话 + 实时工作流可视化),以及
  MCP 服务(供兼容 MCP 的客户端调用)。

## 三、三层能力:Tool / Skill / Agent

平台把"能力"清晰地分成三类,各司其职:

| 层 | 是什么 | LLM 如何使用 | 例子 |
|---|---|---|---|
| **Tool**(工具) | LLM 唯一直接调用的可执行单元 | function-calling 直接调 | `transformer_diagnosis`、`history_lookup`、远程 A2A 工具 |
| **Skill**(技能) | 可加载的领域知识(提示词,`SKILL.md`) | 经内置 `load_skill` 按需加载正文 | `dga-interpretation`(DGA 判读)、`maintenance-report`(检修报告写法) |
| **Agent**(子智能体) | 被委派的自主子任务循环 | 经内置 `spawn_agent` 派生 | explore(只读探索)、general(全能) |

**铁律**:LLM 直接能调的只有 Tool;知识(Skill)和委派(Agent)都"经由 Tool 触达"。
这让能力边界清晰、可审计。

---

## 四、确定性诊断内核

诊断流水线是平台的**护城河**:它是确定性的工作流,不被 LLM 改写。

- **取数**:从时序库拉取评分时序 + 三源识别输入(日志文本 / 油色谱向量 / 图像)。
- **三源缺陷识别**:BERT(日志)、CNN(油色谱)、YOLO(图像)并行识别。
- **证据融合**:D-S 证据理论融合三源,得出缺陷判定 + 置信度。
- **DGA 分析**:油中溶解气体综合风险评分 + 主要威胁。
- **RUL**:物理模型计算健康指数(HI)与剩余寿命(年),严重缺陷可强制覆盖。
- **报告**:汇总成人类可读诊断报告。

四个内层智能体(Coordinator / Data / Diagnosis / Decision)在一张 LangGraph 图上协同,
**三源识别以图级并行执行**,Coordinator 用规则(非 LLM)路由,保证可复现。
整条流水线对外是**一个 Tool**(`transformer_diagnosis`)。

**确定性闸门(golden-trace)**:录制固定输入的确定性输出快照(HI / RUL / 融合判定 /
DGA 风险等,排除 LLM 文本),后续跑诊断与快照逐字段比对,漂移即报错——把"同输入
同输出"焊成一个可执行的测试。

---

## 五、自控 Agent 循环

外层 Supervisor 拥有自己的工具调用循环(ReAct:推理 → 行动 → 观察 → 循环),
通过 OpenAI 兼容接口对接大模型:

- **工具结果防护**:超大结果先存盘只回预览(可按需取回),再截断兜底——大诊断报告、
  远程 JSON 不会撑爆上下文。
- **错误即数据**:工具异常转成字符串回给模型自纠,绝不抛断循环。
- **重试退避** + **迭代上限**,防瞬时失败与弱模型死循环。
- **慢工具异步化**:30-60s 的诊断在线程里跑,不阻塞。

---

## 六、上下文管理

让长对话不超模型窗口,两层分治:

- **单轮内压缩**:一轮里多次工具调用累积的结果,按上下文利用率收缩 / 替换旧结果。
- **跨轮自动摘要**:历史过长时把较早对话摘要成一段并持久化(记录已覆盖的消息边界,
  不重复摘要),只重放"摘要 + 最近若干轮"。摘要专门保留设备 ID、HI/RUL/风险数值、
  故障判定、用户决定。

---

## 七、跨会话记忆 + 技能经验

- **跨会话记忆**:文件式 4 类记忆(用户偏好 / 行为反馈 / 项目进展 / 外部引用),
  维护 `MEMORY.md` 索引注入系统提示;每轮用语义召回(让模型选相关记忆)注入,
  带时效性警告。模型用内置 `save_memory` 工具保存。
- **技能经验记忆**:每个技能配一份经验笔记,加载技能时连同累积经验一起浮现;模型用
  `append_skill_memory` 把可复用教训记下。领域知识因此**越用越懂**(如"C2H2 缓增也按
  电弧报警")。

---

## 八、动态注册与热加载

整个工具/技能注册表可在运行时增删,**不重启进程**:

- **本地工具**:声明式 YAML(`tools.yaml`)加载;或扫描目录(模块级 `TOOL`/`TOOLS` 导出)。
- **远程 A2A 工具**:按 URL 注册(探活拉取对方能力卡)或批量从 YAML 加载;探不到也宽松注册。
- **启用/禁用/移除**:运行时切换。
- 全部入口都暴露到 Web 前端的"能力面板"与 CLI 命令。

---

## 九、子智能体(fork-return)

编排 LLM 可派生子智能体并发处理独立子任务:

- **固定角色**:explore(只读探索)、general(全能);LLM 选角色、写任务,不自由编角色。
- **并发**:一次可派生多个,`asyncio` 并发执行(多设备并行/对比是主场景)。
- **隔离**:子智能体独立上下文,大输出留在子智能体内,只把结论返回父级。
- **安全**:不可嵌套(子智能体拿不到派生工具)、并发上限、错误隔离(子崩不影响父)。

---

## 十、流式输出与前端体验

- **流式**:回复逐字浮现(SSE),不再长时间干等。
- **实时工作流可视化**:每轮以"工作流"面板展示工具 / 技能 / 子智能体的调用,状态
  实时从"进行中"变为"完成/失败",并显示友好标签与关键参数(如"运行变压器诊断 tr01"、
  "派生子智能体 2 个子任务")——用户能看清整条工作流。
- **Markdown 渲染**:诊断报告以富文本呈现(标题/列表/表格/代码),暗色主题适配。
- **会话管理**:历史会话列表、切换、删除、自动恢复最近会话。

前端为独立页"智能体平台",与原有的综合评估 / AI 分析 / 专家复核页并存,互不影响。

| 入口 | 说明 |
|---|---|
| **Web 前端** | "智能体平台"页:流式对话 + 工作流可视化 + 能力热加载面板 |

## 十四、快速开始

```bash
# 后端
conda activate healthAgent
pip install -r requirements.txt
#  在 Config/GlobalConfig.yaml 的 LLM.Agent 配置 DeepSeek key(或留空走本地 Ollama)
python Python/Main.py

# 前端
cd Web && npm install && npm run dev      # 打开后选顶部"智能体平台"页

# 命令行
python Python/Src/Supervisor/chat_cli.py
```

试试:**「同时给 tr01 和 tr02 做体检并对比」**——可看到平台派生两个子智能体并发诊断、
各自调用确定性诊断内核、最终以 Markdown 流式输出对比结论,整条工作流实时可见。
