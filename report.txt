Phase 10 实验报告：自控 Agent 运行时（循环 / 上下文 / 记忆）

报告时间：2026-06-20
阶段：Phase 10（弃用 LangGraph，自写 async Agent 循环 + 单轮内上下文压缩 + 跨轮自动摘要 + 跨会话文件式记忆）
分支：refactor/mcp-multi-agent
参考实现：仿写 Claude Code 的开源教学项目 claude-code-from-scratch
新增依赖：openai（OpenAI 兼容客户端）


================================================================================
一、实现内容
================================================================================

本阶段对 Phase 6-9 的外层 Supervisor 对话层进行了内核级重构，用自主掌控的
异步 Agent 循环替换了 LangGraph 的 create_react_agent 黑盒，并补上了上下文
管理和跨会话记忆两项基础设施。核心交付分为三个子部分：P1 自控循环、P2 上下
文管理、P3 跨会话记忆。

1.1 P1 — 自控 Agent 循环（agent_loop.py）

此前 Phase 6-9 使用 LangGraph 的 create_react_agent 编译一个黑盒工具调用循
环，两个硬伤在实测中暴露：第一，工具调用不稳——本地小模型在黑盒循环里
tool-call 容易出错且无法插桩干预；第二，没有循环级控制——无法插中间件做上下
文压缩、结果防护或错误恢复。Phase 10 对标 claude-code-from-scratch 项目（它
逐章仿写了 Claude Code 的循环、工具、上下文压缩、记忆等机制），用自己的
AgentLoop 类替换掉黑盒。

核心是一个我们完全掌控的 async while 循环。每轮对话进入循环后，系统提示词加
上跨会话历史加上用户输入组成 messages 列表，在最多二十五轮迭代（MAX_TOOL_
ITERATIONS 等于 25）内反复执行以下步骤：首先对 messages 做单轮内压缩（P2 的
预算/裁剪），然后调用 OpenAI 兼容大语言模型的 chat.completions.create，检查
返回消息是否包含 tool_calls——若无则提取文本作为最终答案并退出循环，若有则
逐个派发到对应的工具 dispatch 函数执行，将工具调用结果截断/持久化后以 tool
角色消息追加回 messages，继续下一轮。

与旧实现的对比：循环完全可见、可插桩，每一轮工具调用和返回都在开发者掌控之
中；不再依赖 LangGraph 的 create_react_agent 编译产物。一个关键支点是Ollama
与 DeepSeek 都提供 OpenAI 兼容端点，AgentLoop 使用 openai.AsyncOpenAI 即
可对接两者，切换只改配置文件中的 BaseURL，不需要改动循环代码本身。

结果防护方面实现了三层保护。第一层是截断（truncate_result），超过五万字符的
工具结果保留头部和尾部各一半，中间用省略标记替换——头部保留结构信息（如报告
开篇），尾部保留结论和报错信息。第二层是大结果持久化（persist_large_result），
超过三十 KB 的工具结果完整写入 var/tool-results/ 目录，上下文里仅保留前二百
行的预览加文件路径提示，信息不丢失且不撑爆上下文窗口。第三层是错误即数据
（errors-as-data），工具执行中任何异常都在 dispatch 的 try/except 中被捕获，
转成 "Tool error (name): ..." 字符串返回给大语言模型，循环继续——大语言模型
可以看到错误原因并自行调整策略，异常绝不向上抛出打断整个对话。配合带指数退
避的重试机制（with_retry，对 429/5xx/超时/连接错最多三次），以及慢速同步工
具（如诊断流水线耗时三十到六十秒）通过 asyncio.to_thread 放到线程池执行不阻
塞事件循环，形成了完整的容错体系。

1.2 P2 — 上下文管理（agent_loop.py 内嵌 + core.py 跨轮）

上下文管理分为两个层面：单轮内压缩和跨轮自动摘要，各自解决不同的膨胀来源。

单轮内压缩发生在 AgentLoop.run 的每次大语言模型调用之前。它的触发条件是上下
文利用率——即上一轮调用返回的 prompt_tokens 除以有效窗口大小。有效窗口由模
型名推断（deepseek 一百二十八 K，本地小模型三十二 K），减去八千 Token 余量，
并可通过配置文件中的 EffectiveWindowOverride 强制覆盖。

当利用率超过零点五时启动预算压缩（budget），将所有已累积的 tool 角色消息中
超过预算上限的部分从中间截断——利用率高于零点七时预算收紧到一万五千字符，否
则三万字符。当利用率超过零点六时启动裁剪（snip），只保留最近三条工具结果的
完整内容，更早的工具结果正文替换为"[旧工具结果已省略 — 如需可重新调用]"占
位符。这套机制是纯本地计算，不需要额外 API 调用，在每次大语言模型请求前以极
低成本运行。

跨轮自动摘要发生在 core.py 的 _maybe_compact_and_load 方法中，在每轮对话加
载历史之前触发。因为我们的跨轮历史只存储 user 和 assistant 最终文本（不含
tool 中间消息），所以任意位置切片都安全——不会切断 tool_use 与 tool_result
的配对。处理流程是：先从 session_summaries 表读取当前会话的已有摘要和它覆盖
到的消息 ID（covered_until），然后从 messages 表加载该 ID 之后的所有消息。
估算系统提示词加上这些消息的总 Token 数，若超过有效窗口的零点八五倍且消息数
量超过最近六条，则触发摘要。摘要时把最近六条消息保留为原文，更早的消息交给
AgentLoop.summarize 方法（又是一次大语言模型调用，但使用专门的低温度摘要提示
词）压缩成一段中文摘要，摘要提示词明确要求保留设备编号、健康指数、剩余寿命、
风险评分、故障判定和用户决定。摘要结果持久化到 session_summaries 表，记录新
的 covered_until 值，下次加载时只读"摘要加上该 ID 之后的消息"，不会重复摘要
同一段对话。

1.3 P3 — 跨会话记忆（memory.py）

记忆系统采用文件式存储，所有记忆文件放在 var/memory/ 目录下，每个文件有
YAML frontmatter（name、description、type）加 Markdown 正文，文件名格式为
{type}_{slug}.md。特别注意 slug 的生成保留 Unicode 字符，否则中文记忆名会全
部塌缩成同名文件互相覆盖。

记忆分为四种类型。user 类型记录用户身份、偏好和背景；feedback 类型记录对平
台行为的纠正或肯定性反馈，正文中必须写明为什么以及如何应用这条反馈；project
类型记录进行中的目标、决策和截止日期，相对日期需转为绝对日期；reference 类
型记录外部系统的定位信息（看板地址、工单号、URL 等）。系统提示词中注入了保
存记忆的指导规则，明确告诉大语言模型：只保存不能从代码或诊断数据中推导出来
的信息；四种类型各有适用场景；不要保存临时或琐碎内容。

保存机制采用内置的 SaveMemoryTool，大语言模型像调用其他工具一样调用它，传入
名称、描述、类型和内容四个参数。保存后自动生成或更新 MEMORY.md 索引文件——
它是 var/memory/ 目录下的一个 Markdown 文件，每行列出一条记忆的文件名、类型
和描述，并注入到每轮对话的系统提示词中。

召回机制采用语义匹配而非关键词匹配。每轮对话时 core.py 的 _recall_memories
方法被调用，它通过 AgentLoop.side_query 向大语言模型发起一次微型补全请求——
把记忆索引（文件名加描述）发过去，让大语言模型在语义上判断哪些记忆与当前的
用户输入相关，返回匹配的记忆文件名列表。命中的记忆正文被读取并作为系统提醒
注入到历史消息中。召回机制设置了多重门控：单词查询（不含空格）自动跳过，不
浪费这次 sideQuery 往返；每个会话有六十 KB 的累计召回预算，超出后不再触
发；同一会话内已召回过的记忆自动去重不重复注入。超过一天的记忆还会附带
freshness 警告，提醒大语言模型该记忆可能已过时。

1.4 动态注册的去重编译化

因为弃用了 LangGraph 的 create_react_agent，工具的注册/启用/禁用不再需要
"重编译图"。Supervisor 内部将工具存为 OrderedDict，每次 chat 轮开始前从
_active_tools 方法实时读取活跃工具列表（启用的用户工具加上LoadSkillTool和
SaveMemoryTool两个内置工具），直接传给 AgentLoop.run。新增、删除、禁用或
启用工具均为对 OrderedDict 和 disabled 集合的纯数据操作，无任何重建开销。
这是弃用 LangGraph 循环黑盒带来的附带收益——动态注册变得更轻量。

1.5 配置与模型切换

通过 GlobalConfig.yaml 的 LLM.Agent 段配置后端。BaseURL 指向 DeepSeek 的
v1 端点或 Ollama 的 localhost:11434/v1，APIKey 若不是 YOUR_ 占位符则走远端
Agent，否则自动回退到 Ollama 本地。ModelName 直接传给 openai.AsyncOpenAI 的
model 参数。整个切换对 AgentLoop 完全透明，它只看到 OpenAI 兼容接口。


================================================================================
二、存在问题
================================================================================

2.1 记忆召回是串行的

每轮对话在加载历史之后、正式对话之前，多了一次 sideQuery 往返来召回相关记
忆。参考项目 claude-code-from-scratch 用异步预取与首个大语言模型调用并行，
我们的实现是同步串行的——用户感知不到明显延迟（sideQuery 是很小的补全，不
用工具，max_tokens 仅二百五十六），但在高压场景下累积。虽然门控机制（单词
查询跳过、预算耗尽跳过）已减少了无谓调用，但尚未实现预取并行化。

2.2 未做流式输出

AgentLoop.run 的最终答案是 text 一次性返回的，没有实现流式（streaming）。
对于变压器诊断场景，主要耗时在工具内的诊断流水线（三十到六十秒），而非大语
言模型的生成阶段，流式输出的收益有限。但如果未来需要"正在调用 X 工具"的实
时进度提示或长文本逐步生成，需要加 SSE 推送。

2.3 单轮内压缩作用于已累积的消息

budget 和 snip 压缩每次大语言模型调用前运行，但它们压缩的是当前轮已累积在
messages 列表中的工具结果。这意味着如果第一轮调用就返回了一个超大的工具结果
（比如诊断报告的原始 JSON 有数十 KB），它会在第二轮调用压缩生效之前就已经占
据了一次完整的上下文窗口。压缩是事后防御，不是事前预算控制。

2.4 跨轮摘要依赖大语言模型质量

AgentLoop.summarize 使用大语言模型做对话摘要，保留"设备编号、诊断数值、故障
判定、用户决定"。摘要质量取决于大语言模型的遵守程度。如果模型漏掉了关键数值
（比如把健康指数 81.93 摘要成了"约八十"），后续对话中追问精确数值时会丢失
精度。目前没有对摘要内容做数值校验。

2.5 记忆的 freshness 警告较粗糙

对于超过一天的记忆，系统仅附加"[本记忆已创建超过 N 天，内容可能已过时，请
核实]"的警告，但没有按记忆类型或内容做更细粒度的过期判断。project 类型的记
忆（如"九月检修"）在九月份过后应该自动标记为完成或失效，目前仍需手动管理。

2.6 内层诊断图的静态性仍然存在

Phase 10 改造的仅是外层 Supervisor 的循环引擎和上下文/记忆基础设施。内层
LangGraph 诊断图（Phase 3-5）的节点和边仍然是手工连接的——虽然 Coordinator
的路由是注册表驱动的，但图的拓扑结构不会在运行时变化。将远程智能体嵌入诊断
流水线内部（如在 fusion 之后插入复核节点）目前仍不可行。

2.7 子 Agent 和权限钩子未实装

参考项目 claude-code-from-scratch 支持子 Agent（fork-return 模式，七种角色）
用于并行分析和独立探索，以及危险域操作的权限确认钩子。我们的平台目前没有这
两项能力。多设备并行诊断需要在上层手动循环调用，探索性任务（如"扫描所有设
备找出风险最高的三台"）没有内置的子任务委派支持。

2.8 前端对话组件未适配新返回格式

AgentConsole 的对话区域目前展示工具调用标签（显示名称），但 Phase 10 新增
的大结果持久化提示（"[结果过大，完整内容已存到 var/tool-results/xxx.txt]"
在前端仅是纯文本展示，未做文件下载或展开阅读的交互。跨轮摘要后的"[对话摘要]"
消息在前端也未做视觉上的差异化处理，用户看不出哪些内容是被压缩过的历史。
